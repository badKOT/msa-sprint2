### Migration strategy, описанная в task1/resuls/ADR:

1. Выделить сервис. Он временно подключается к общей бд вместе с другими сервисами
2. Переключить монолит: теперь для операций с entity не вызываем бд напрямую. Instead, отправляем запросы к сервису, который отвечает за работу с этой entity.
3. Если вышеуказанная entity используется в бизнес-сценариях за пределами выделенного микросервиса, нужно добавить views, чтобы эти другие сценарии могли читать данные.
4. Внедрить систему событий и обновления вьюшек (в будущем -- реплик).
5. Физически разделить базы данных. Это может быть разделение на схемы или совсем радикальное, на базы данных.

В реализованной версии мы выполнили шаг 2. Монолит не выполняет запросы напрямую к бд. Вместо этого, все операции с booking-ами выполняются через booking-service (надеюсь, что это так, сорсы декомпилировать лень).
Дальше нужно определить, используются ли букинги в других сценариях. Если да, пройти по шагам 3 и 4. Иначе переходим к шагу 5 и выделяем таблицу.
